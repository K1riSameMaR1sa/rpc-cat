# RPC CAT · 管理局翻译工作台

给 RPC 管理局（RPC Authority）译者用的**纯前端**翻译辅助工具：

- **对齐制作** —— 粘贴英文原文 + 中文译文，自动做段落级／句级对齐，人工可修正，一键生成 **TMX**
- **翻译记忆库** —— 导入／导出 TMX，检索、编辑、去重、合并；语料存在浏览器本机
- **CAT 式工作台** —— 逐句翻译，自动给出 100% 精确匹配与模糊匹配百分比，查证检索，进度统计
- **语料库** —— 保存翻译项目，随时继续翻译或导出纯译文

没有后端，没有上传，没有账号。所有数据保存在你自己浏览器的 IndexedDB 里。
可以直接托管到 GitHub Pages。

---

## 快速开始

### 最简单：双击 `rpc-cat.html`

仓库里的 **`rpc-cat.html`** 是**单文件版**：样式、脚本、示例记忆库全部内联在
一个文件里，**直接双击就能用**，不需要服务器、不需要联网。

> 为什么不能双击 `index.html`？浏览器出于安全策略，
> **禁止 `file://` 下加载 ES 模块**，脚本会被整个拦掉，
> 表现就是「页面能打开，但所有按钮都没反应」。
> `index.html` 是给本地开发和 GitHub Pages 用的；
> 如果你双击了它，页面会在 1.5 秒后弹出提示告诉你该怎么办。

### 本地运行（开发用）

ES 模块需要一个 HTTP 服务：

```bash
git clone <your-repo-url>
cd rpc-cat
npm run serve          # 然后打开 http://localhost:8080/
```

没有 Node 也可以用任意静态服务器，例如 `python -m http.server 8080`。

### 部署到 GitHub Pages

1. 把仓库推到 GitHub。
2. **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。
3. 仓库自带的 `.github/workflows/pages.yml` 会自动构建单文件版、跑测试并发布，
   地址形如 `https://<用户名>.github.io/<仓库名>/`。

> 也可以把 Source 选成 **Deploy from a branch**（分支 `main`、目录 `/ (root)`），
> 一样能用，因为整个应用就是静态文件。

### 改完代码后

```bash
npm run build          # 重新生成 rpc-cat.html
npm test               # 四组测试
```

`rpc-cat.html` 是**构建产物，但建议一起提交**，这样别人 clone 下来就能直接双击用。
它由 `js/` 下的 ES 模块生成——那些才是唯一的事实来源，别直接改 `rpc-cat.html`。

## 功能说明

### 0. 原格式保留（重要）

原文**不会被展平**。工作台按行解析，逐块保留结构：

| 结构 | 处理方式 |
|---|---|
| 换行、空行、缩进 | 原样保留，导出时按原结构回填 |
| `[[code]]…[[/code]]`、``` 围栏 | **整块不翻译、不参与断句**，原样透传 |
| `\|\|表格行\|\|` | 拆成单元格翻译，`\|\|` 与 `~` 表头标记保留 |
| `[[module]]`、`[[include]]`、`[[collapsible]]`、`[[footnote]]` | 标记行不翻译；**行内标记不会被断句切碎** |
| `* 列表`、`+ 标题`、`> 引用` | 标记保留，只翻译标记之后的内容 |

导出的是**可以直接贴回 Wikidot 的完整文件**：未翻译的句子回退为原文，
代码块与标记原样输出，不会丢内容。有「预览输出」可以先看一眼再下载。

> 实现上，一段文字切成句子时会同时记下句间的空白（含换行），回填时逐句拼回；
> `[[…]]`、`@@…@@`、`**…**`、URL 等在断句前被**等长掩码**替换，
> 所以内部出现的 `.` 和 `。` 不会造成误断。
> `tests/document.mjs` 有一组「解析后重建必须与原文件逐字节相同」的回归测试。

### 1. 总记忆库（载入免费，写入需口令）

站点自带完整的 RPC Authority 中英记忆库：**29,271 条**，gzip 后 2.87 MB
（`data/rpc-memory.tmx.gz`）。它**不会自动写入**你的浏览器，必须显式载入：

「设置 → 总记忆库 → 载入总记忆库」，勾选授权条款后，二选一：

| 方式 | 是否需要口令 | 效果 |
|---|---|---|
| **只本次使用，不写入**（默认） | **不需要** | 索引只放在内存里供本次查证，关掉页面即消失 |
| **写入本机记忆库** | **需要管理员口令** | 长期保留，翻译时自动匹配 |

设计上区分了「用」和「存」：读一份数据放进内存不消耗任何东西、也不留下任何东西，
所以不设门槛；而**往你浏览器里写一份副本**才是需要有人把关的动作，
口令就是拦在这一步。

「不写入」很适合只想查证一下、又不想让浏览器多占几十兆的情况——
代价是每次打开都要重新载入一次。

**软门禁的边界，请务必理解**：这是纯前端页面，没有服务器。
口令只是比对哈希，数据本身就是同目录下的公开文件——打开开发者工具就能拿到。
它能保证的是**没人能误操作把整库灌进本地数据库**，以及**由你决定把口令发给谁**，
而不是真正的访问控制（尤其不能阻止别人读）。要真正的保护，得配后端。

更换口令：

```bash
npm run set-code -- 你的新口令     # 只写入 SHA-256，口令本身不落盘
npm run build                      # 重新生成单文件版
```

仓库预置的是默认口令 `rpc-admin`，`data/config.json` 里的
`adminCodeIsDefault: true` 会让界面持续提示更换。**首次部署请务必换掉。**

### 2. 对齐制作（生成 TMX）

分别粘贴英文原文和中文译文 → **自动对齐** → 检查表格 → **存入记忆库** 或 **导出 TMX**。

对齐算法与离线构建总记忆库的流程完全一致：

1. **段落级单调动态规划**。相似度由跨语言特征合成：
   - **锚点重合** —— 编号（`RPC-691`、`Site-070`）、日期（`5/12/2017`、`2017年5月12日`、
     `16-17 July, 1462` 都会归一化成同一种标记）、小数、百分数；
   - **结构标签** —— `Object Class:` ↔ `项目分级：`、`Containment Protocols:` ↔ `收容协议：` 等；
   - **长度合理性** —— 以**该段自身**的中英长度比为准，而不是全局常数；
   - **必须保留的标识符** —— 含数字的记号（`RPC-691`、`MP4`、`3.75G`）译文中通常原样保留，
     若一侧有而另一侧完全没有，就说明多半不是一对。
   跳过段落是**零成本**的，配对必须超过阈值才会成立，所以无关段落不会被硬凑成一对。
   **代码块与标记行不参与对齐。**
2. **句级对齐**。两侧句数相同就 1:1 直配；否则用小型单调 DP 分组，置信度不足时整段作为一条输出。

表格里可以手动 **并入上一行 / 并入下一行 / 拆分为两句 / 取消配对 / 删除该行**。

### 3. 翻译记忆库

- 导入 TMX / **TMX.GZ** / CSV / JSON
- 检索（支持正则，写作 `/pattern/`）、编辑、单条或批量删除、跨库移动
- 删除完全重复条目；统计同一源文的多译法
- 导出 TMX（可导入 Trados、memoQ、OmegaT、CafeTran 等）、CSV、JSON

### 4. 工作台

粘贴原文后按结构解析，逐句翻译：

- 展示记忆库匹配（100% 精确 / 模糊百分比），点击即填入译文
- 高亮 `███`、`[[...]]`、`RPC-XXX`、数字等**必须原样保留**的内容
- 译文若漏掉原文中的编号，会就地提示「缺少 …」
- 代码块、标记行、空行只读显示，但完整保留在导出结果里
- 快捷键：`Ctrl+Enter` 确认并下一句，`Esc` 关弹窗

可导出 **译文（保留原格式）**、**双语 TMX**，或先「预览输出」。

### 5. 语料库

翻译项目保存在这里，可以继续翻译、导出 TMX、导出纯译文，或一键存入记忆库。

## 内置示例记忆库

仓库里的 `data/demo-tm.tmx` 是从完整记忆库里抽出的 **660 条**高质量对照
（涵盖 RPC 主条目、故事、设定页等 30 个页面），无需口令即可试用。

**完整的 RPC Authority 中英记忆库 29,271 条**放在 `data/rpc-memory.tmx.gz`
（gzip 后 2.87 MB，原始的 21 MB 不适合进 git），载入需要授权确认与管理员口令，
详见上面的「总记忆库」一节。

## 项目结构

```
rpc-cat.html            ★ 单文件版（构建产物，双击即用）
index.html              应用外壳（开发 / GitHub Pages 用，需要 HTTP 服务）
css/style.css           主题样式
js/
  app.js                状态、路由、记忆库装载、导入导出、临时记忆库
  master.js             总记忆库：config、SHA-256 校验、gzip 解压、授权门禁
  document.js           原格式解析与重建（代码块 / 表格 / 标记 / 句间空白）
  ui.js                 DOM 小工具、弹窗、通知、文件读写
  tmx.js                TMX 1.4 解析与生成（无依赖，含 CDATA / 实体）
  segment.js            断句、锚点抽取、结构标签
  align.js              跨语言对齐（段落 DP + 句级 DP）
  match.js              模糊匹配引擎（倒排索引 + 编辑距离）、查证检索
  db.js                 IndexedDB 存储层
  views/                workbench / align / memory / corpus / settings
tests/
  run.mjs               逻辑单元测试（TMX 往返、断句、锚点、对齐、模糊匹配）
  document.mjs          原格式：重建必须与原文逐字节一致
  master.mjs            总记忆库文件、gzip、SHA-256、门禁配置
  smoke.mjs             在 DOM 垫片上真实渲染每个视图
  dom-shim.mjs          极简 DOM，用于在 Node 里跑视图
  db.mjs                存储层测试（真实调用 db.js）
  idb-shim.mjs          内存版 IndexedDB
  bundle.mjs            启动单文件版，真的去点按钮、过门禁
scripts/
  serve.mjs             本地静态服务器
  bundle.mjs            生成 rpc-cat.html（--with-master 可把总库内联）
  make-master-memory.mjs 从完整 TMX 生成 data/rpc-memory.tmx.gz
  set-admin-code.mjs    设置管理员口令（只写哈希）
  make-demo-tm.py       从完整 TMX 抽取示例库
data/
  config.json           授权条款、口令哈希、总库元信息
  rpc-memory.tmx.gz     总记忆库（29,271 条，2.87 MB）
  demo-tm.tmx           示例记忆库（660 条，无需口令）
```

## 测试

```bash
npm test                # 六组全跑
npm run test:unit       # TMX 往返、断句、锚点、对齐、模糊匹配
npm run test:document   # 原格式解析与逐字节重建
npm run test:master     # 总库文件、gzip、SHA-256、门禁配置
npm run test:smoke      # 在极简 DOM 上渲染每个视图
npm run test:db         # IndexedDB 存储层（内存版 IDB）
npm run test:bundle     # 启动单文件版，逐个点击按钮验证真的有效
```

- **单元测试**覆盖 TMX 往返（含 CDATA 与实体）、中英断句、锚点抽取、
  跨语言对齐（带省略号错位与年表错位的回归用例）、模糊匹配与查证检索。
- **原格式测试**保证「解析 → 重建」与原文件**逐字节相同**（CRLF 归一化除外），
  覆盖代码块、表格、标记行、列表、缩进、纯空白等边界情形。
- **总库测试**校验 gzip 往返、SHA-256 与 `node:crypto` 一致、
  `config.json` 声明的条数与体积和实际文件相符、默认口令确实是文档里那个。
- **冒烟测试**在一个极简 DOM 上真实调用每个视图的 `render()`，
  抓「导入了不存在的导出名」「渲染时抛异常」这类问题。
- **存储层测试**用一个内存版 IndexedDB 跑通真实路径：
  建库 → 导入全部 660 条 → 读回 → 建索引 → 检索 → 编辑 → 删除。
- **单文件版测试**会真的加载 `rpc-cat.html`、点导航按钮、导入示例库、点「开始翻译」、
  点匹配建议，并**完整走一遍总记忆库门禁**：
  不勾授权被拒；**不输入任何口令**即可用「只本次使用」载入成功；
  切到「写入」后空口令被拒、错口令被拒；输对口令才真正写入——
  并断言前两步之后数据库里**一条都没多**。
- CI（`.github/workflows/pages.yml`）在发布前会构建单文件版并跑全部六组测试。

## 隐私

所有数据都在浏览器本地（IndexedDB）。工具不会向任何服务器发送内容。
换浏览器或清理浏览器数据会丢失内容，请用 **导出 TMX** 定期备份。
